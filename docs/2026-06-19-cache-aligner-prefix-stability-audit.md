# CacheAligner prefix-stability audit (Dioscuri AC-2 · DIO-1)

AI-assisted: generated by Claude, reviewed by a human.

**Phase-0 gate.** This audit de-risks all Dioscuri injection work (PRD §3 AC-2;
ticket DIO-1). It proves the rendered identity/rules prefix — the stable,
cache-aligned head of the system context — contains **no per-session-volatile
token**, and freezes a byte-exact baseline the AC-2 prefix-stability test diffs
against. Read-only: it documents state and mutates nothing.

## Why this gate

The injection pipeline's core safety claim (AC-2) is that all injected content lands
**downstream of the stable prefix**, in the volatile tool-result tail — it never
writes into, reorders, or mutates the identity/rules prefix or Layer 1. That claim
only holds if the prefix is genuinely *stable*. If a per-session-volatile token (an
ISO timestamp, `Date.now()`, a `$(date)` shellout, a sessionId, a PID, a run/turn
counter, epoch seconds, a UUID) sat inside the prefix, the prefix bytes would shift
every session — defeating prefix caching AND giving the pipeline a moving boundary
to land against. So before any injection seam ships, we establish the baseline here.

## Prefix surface audited

The rendered prefix is assembled from three template families, in load order:

1. `templates/CLAUDE.md` — the neutral body
2. `templates/personality.md` — the `@`-imported per-machine soul
3. `templates/rules/*.md` — user-scoped rules (`communication.md`, `tooling.md`),
   sorted for deterministic order

Each is rendered through `envsubst` exactly as the install path does
(`install.sh` ~150-176; `update.sh` 8.4/8.6 ~398-438) — same binary, same
variable-restriction string.

## The threat model (what is and isn't flagged)

`envsubst` substitutes only these per-machine-stable vars: `USER_NAME`,
`AGENT_NAME`, `MACHINE_DESC` (and `DEV_ROOT`, kept on the exclusion list defensively
though today's render path does not use it). These are set **once at install**, not
per session — so they are the *expected* prefix variability and are **excluded** from
the volatile scan. Flagging them would be a false-positive bug. The harness excludes
them by rendering them to fixed test literals before scanning; the scan targets only
the per-session-volatile shapes.

To make the artifact machine-independent and deterministic, the harness renders with
**fixed test values** (not the live machine's identity):

```
USER_NAME = TestUser   AGENT_NAME = TestAgent
MACHINE_DESC = test-machine   DEV_ROOT = /test/dev/root
```

One boundary case worth recording: `templates/rules/tooling.md` lists `date` as an
allowed Bash command (a markdown code-span of the literal word). That is
documentation, not an output-producing shellout, so it is correctly **not** flagged —
the `date-shellout` detector requires the executing form (`$(date ...)` or
`` `date +%s` `` with a flag), never the bare word.

## Reproduce

From the repo root:

```
# Human audit report (this document's Result section, live):
node scripts/cache-aligner-audit.js

# Machine-readable report:
node scripts/cache-aligner-audit.js --json

# Regenerate the committed baseline (deterministic — same command twice is byte-identical):
node scripts/cache-aligner-audit.js --emit-baseline > hooks/test/fixtures/prefix-baseline.txt

# Run the gate (repo convention; Node 20 floor auto-discovers the directory):
node --test hooks/test/
#   On Node 22+ where the bare-directory form is not a glob, use:
#   node --test "hooks/test/*.test.js"
```

The test suite covers: render determinism (two renders byte-identical), baseline
match (rendered prefix == committed baseline), the live AC-2 assertion (zero volatile
findings), the stable-var false-positive guard, and — as anti-sandbagging — a
**planted-token** case per detector that asserts the scan actually catches each
volatile shape (a scan that can only ever say PASS proves nothing).
